## Section 3: Present — Understanding-Driven Learning (250 words)

**Purpose:** Argue that AI shifts developer learning from memorizing APIs to understanding architecture, trade-offs, and system design

**Personal Experience?** No — General section, AI can write

**Key Points:**
1. AI handles the "what" (syntax, API calls, boilerplate)
2. Developers now need the "why" (architecture decisions, trade-offs, edge cases)
3. Example: Before AI, you memorized React lifecycle. Now you need to understand when useEffect runs and why

**Supporting Evidence:**
- Study: Copilot reduces keystrokes by 55% but increases code review time
- Industry shift: "prompt engineering" is a new skill category

**Tone Notes:**
This is the core argument — make it compelling

**Transitions:**
- **From previous:** Unlike the old model...
- **To next:** But this shift isn't without risks

**Self-Check Questions:**
- Is the "why not what" distinction clear?
- Does the React lifecycle example resonate?

**内容充实度铁律:**
- [ ] 具体数据 — 55% keystroke reduction
- [ ] 技术机制 — 说明 AI 如何接管记忆层（LLM 的 pattern matching 机制）
- [ ] 案例/反例 — React useEffect 具体例子

## Section 4: Challenge — Hallucination & Blind Spots (150 words)

**Purpose:** Acknowledge the risks of over-relying on AI: misinformation, skill atrophy, and blind spots

**Personal Experience?** No — General section, AI can write

**Key Points:**
1. AI hallucination: confident but wrong code
2. Skill atrophy: "use it or lose it" for debugging skills
3. Blind spots: AI can't evaluate architecture trade-offs

**Supporting Evidence:**

- Developer anecdotes: "I spent 3 hours debugging generated code that was wrong"

**Tone Notes:**

**Transitions:**
